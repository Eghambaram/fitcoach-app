# Cloudflare R2 — file storage

FitCoach stores files in Cloudflare R2 (PROMPT §17.7, ADR-0011, ADR-0041). Locally RustFS stands in with the same S3 API. Only the `STORAGE_*` values differ. This guide sets up **staging**. Production buckets, the `media.<domain>` custom domain and backups follow in step 6.2.

## How the app uses R2

| Bucket                   | Holds                                                             | Access                                                                         |
| ------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `fitcoach-<env>-private` | client avatars (later), exports, database backups (6.2)           | Never public. The API issues presigned GETs (≤ 5 minutes) after an auth check. |
| `fitcoach-<env>-public`  | trainer profile photos, public-page photos, global exercise media | Public read: r2.dev URL on staging, `media.<domain>` on production.            |

- Uploads always go through the API (type and size checks, EXIF stripped, WebP + thumbnail). Browsers never upload to R2 directly, so **no CORS rules** are needed.
- Object keys are immutable UUIDs (`trainer-avatars/<workspace>/<uuid>.webp`), so cached copies never need purging.
- The API checks readiness by reading a key that doesn't exist (`health/readiness-probe`) in each bucket. `NoSuchKey` means reachable and authorised. That's one Class B read per bucket per check.

## Free tier and the app's budget

The free tier is **per Cloudflare account**, shared by staging and production: 10 GB-month storage, 1 M Class A operations (writes, lists), 10 M Class B operations (reads), and free egress. Above that, Cloudflare bills you. The app enforces its own limits from the `files` ledger:

- `STORAGE_BUDGET_BYTES` (8 GiB): readiness reports storage "degraded".
- `STORAGE_HARD_LIMIT_BYTES` (9 GiB): new uploads are refused with a clear message.

Keep staging small: a handful of test photos is plenty.

## Step by step (staging)

### 1. Enable R2

1. Cloudflare dashboard → **R2 Object Storage**. Activation may ask for a payment method even if you stay within the free tier.
2. Copy your **Account ID** (R2 overview page, right-hand side). The S3 endpoint is `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

### 2. Create the buckets

R2 → **Create bucket**, twice:

| Name                       | Location                               | Storage class |
| -------------------------- | -------------------------------------- | ------------- |
| `fitcoach-staging-private` | Location hint: **Asia-Pacific (APAC)** | Standard      |
| `fitcoach-staging-public`  | Location hint: **Asia-Pacific (APAC)** | Standard      |

Use Standard storage: Infrequent Access has no free tier.

### 3. Public access for the public bucket only

1. `fitcoach-staging-public` → **Settings** → **Public access** → **R2.dev subdomain** → **Allow**, then confirm.
2. Copy the URL shown, e.g. `https://pub-0123abcd….r2.dev`. This is `STORAGE_PUBLIC_BASE_URL` (no trailing slash, no bucket name).
3. `fitcoach-staging-private` → **Settings** → make sure the R2.dev subdomain is **not allowed** and no custom domain is connected.

r2.dev URLs are rate-limited and meant for testing, which is fine for staging. Production uses a custom domain (step 6.2).

### 4. API token for staging

1. R2 → **Manage R2 API Tokens** (or **API** → **Manage API tokens**) → **Create API token**.
2. Name: `fitcoach-staging`.
3. Permissions: **Object Read & Write**.
4. Specify buckets: **Apply to specific buckets only** → `fitcoach-staging-private` and `fitcoach-staging-public`.
5. TTL: forever (rotate it by creating a new token and updating Railway).
6. **Create** and copy the **Access Key ID** and **Secret Access Key** right away. The secret is shown once. Put them only in Railway variables, never in the repo or chat.

### 5. Lifecycle rules (private bucket)

`fitcoach-staging-private` → **Settings** → **Object lifecycle rules** → **Add rule** for each:

| Rule name            | Prefix            | Action                                         |
| -------------------- | ----------------- | ---------------------------------------------- |
| `exports-1d`         | `exports/`        | Delete objects after 1 day                     |
| `backups-daily-8d`   | `backups/daily/`  | Delete objects after 8 days                    |
| `backups-weekly-35d` | `backups/weekly/` | Delete objects after 35 days                   |
| `abort-multipart-1d` | (whole bucket)    | Abort incomplete multipart uploads after 1 day |

Nothing writes those prefixes yet (exports and backups come later). The rules are a safety net in place from day one.

### 6. Put the values in Railway

In the Railway `staging` environment → `api` service → Variables (see [railway.md](railway.md#3-api-service)):

```env
STORAGE_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
STORAGE_REGION=auto
STORAGE_ACCESS_KEY_ID=<Access Key ID>
STORAGE_SECRET_ACCESS_KEY=<Secret Access Key>
STORAGE_PRIVATE_BUCKET=fitcoach-staging-private
STORAGE_PUBLIC_BUCKET=fitcoach-staging-public
STORAGE_PUBLIC_BASE_URL=https://pub-<id>.r2.dev
STORAGE_KEY_PREFIX=
```

Set all of them or none. With only some set, the API refuses to start and names the missing ones. With none set, uploads answer "not configured".

### 7. Verify

1. `https://<web domain>/api/v1/health/ready` shows `"storage":{"status":"ok", …}`.
2. Upload a profile photo on staging. R2 → `fitcoach-staging-public` → **Objects** shows `trainer-avatars/<workspace id>/<uuid>.webp` and `<uuid>_thumb.webp`.
3. Remove the photo in the app. The object stays for 7 days (soft delete), then the nightly purge job removes it.

## PR environments (optional)

If you enable Railway PR environments later, they share the **staging** buckets and token with `STORAGE_KEY_PREFIX=pr-<number>/`. Delete that prefix in R2 when the PR closes.

## Troubleshooting

| Symptom                                                 | Check                                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Readiness `storage: degraded`, logs show `AccessDenied` | Token not scoped to both buckets, or wrong access key/secret.                                                                               |
| Logs show `NoSuchBucket`                                | Bucket name typo in `STORAGE_PRIVATE_BUCKET` / `STORAGE_PUBLIC_BUCKET`.                                                                     |
| Uploads fail with a checksum or signature error         | Endpoint must be `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` with region `auto`. The client already sends checksums only when required. |
| Photo uploaded but the image 404s                       | `STORAGE_PUBLIC_BASE_URL` wrong or r2.dev access not allowed on the public bucket.                                                          |
| Image loads slowly or returns 429                       | r2.dev rate limit (testing only). Production uses the custom domain.                                                                        |
