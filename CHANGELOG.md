- Step 3.5 live workout logging (PROMPT §8.5):
  - **`/app/workouts/[id]`** (opened from Client profile → Workouts):
    - **Before it starts:** the planned workout, with Start and Skip.
    - **In progress:** the current exercise with its media (or a placeholder); reps/time and weight steppers; a rest timer; the set list (target vs actual); a big Complete set; Add set; Mark not done; Previous / Next exercise; Swap (library suggestions or any exercise); Add exercise; and an "X of Y exercises completed" bar.
    - **Layout:** on desktop the exercise list sits beside the current exercise; on phones it's behind a toggle.
    - **Finish workout** shows a summary (exercises, sets, volume, duration) and takes feedback. The summary offers **Mark attended** for the linked session, which uses one package session.
  - Every set is saved as it is completed, with an id made on the device. A refresh restores everything and a retry never duplicates a set. Saves are disabled while offline.
  - **API:** `GET /v1/workout-sessions/:id`, `POST /v1/workout-sessions/:id/start|finish|skip|exercises` (finish takes Idempotency-Key), `PUT /v1/workout-sets/:id`, `POST /v1/workout-session-exercises/:id/substitute`.
  - **Database:** `workout_session_exercises`, `workout_sets`; workout session lifecycle, appointment link, feedback and skip reason. ADR-0054.
  - **Tests:**
    - **RLS:** writes only while in progress; lifecycle CHECK; finished is final; no deletes; foreign exercises and appointments refused; one workout per appointment; cross-tenant; empty context; suspended workspace.
    - **API:** preview without side effects; starting twice; repeated and lost-id set saves; ordering and validation; substitution; added exercise; finish idempotency; finished is history; attendance deducts once; skip; tampering.
    - **e2e:** logging with a refresh mid-way, then Mark attended, on desktop and mobile.

### Fixed

- Package session use listed a switched mark (attended → no-show) in random order: the reversal and the new mark share the transaction's timestamp, so the tie was broken by UUID. The reversal now always comes first.
- E2E accessibility checks run with reduced motion, so axe never samples a toast mid-fade (CI reported contrast "failures" of 1.4–4.3:1 that were transitions, not colours).
- Leads and clients lists: a debounced search, or two quick filter changes, could undo a filter chosen just before. Filters now always build on the newest URL (`useUrlQuery`).
- Drawers with only read-only content can now be scrolled from the keyboard (axe `scrollable-region-focusable`).
- Package and exercise contracts: nullable strings carry a length bound, so the generated API client types them as strings.
- Success, error, warning and info toasts now use the design tokens; sonner's default success green failed WCAG AA contrast (4.25:1).
- The clients list and profile never showed a next session: the correlated subquery bound the outer client columns to the appointment (step 3.1).
- The generated API client typed plain nullable strings in new contracts as arrays; nullable strings now carry a length bound (as the existing contracts do).
- Lead note timestamps had insufficient colour contrast (axe).
- The typed API client resolved every response to `any`: it emitted `createClient.Client<…>` into its declaration file. It now declares its return type, so the web is type-checked against the real contracts again.
- OpenAPI: bare nullable scalars (`z.string().nullable()`) were published as arrays of strings (e.g. sessions' `userAgent`); they're now `string | null`.
- The enquiry form's optional training-mode radio sends `null` when untouched; the contract accepts it (previously the form would silently refuse to send).

### Changed

- The API image migrates on start (`migrate.js && exec main.js`) instead of relying on Railway's pre-deploy command, which the staging setup didn't run. `railway.json` loses `preDeployCommand`/`startCommand`, services set `RAILWAY_DOCKERFILE_PATH`, compose drops the `api-migrate` service, and the Railway guide covers the Railpack and `28P01` symptoms (ADR-0043).
- Storage readiness reads a non-existent key (`NoSuchKey` = reachable) instead of `HeadBucket`, which bucket-scoped R2 tokens may refuse. A misspelled bucket now reports "degraded" (ADR-0042).
- The smoke spec checks the API through the web's `/api` proxy, so it also runs against deployed environments.
- Phase 2 reordered: conversion (2.4) → onboarding (2.5) → calendar (2.6), so recurring series have real clients (ADR-0028).
- Node 24 LTS replaces Node 22 in the spec and Dockerfile sketch (ADR-0026).
- Local object storage is RustFS instead of MinIO in PROMPT.md, CLAUDE.md and PHASES.md (ADR-0036).
- `--muted-foreground` token `#6C756F` → `#6A736D` (ADR-0037).
